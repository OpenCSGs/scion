In this release `scn` takes git's spellings of everyday commands and options. A working copy can move to a server's new address, and `--help` describes every argument with examples. The server is unchanged since v0.1.4.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

The packages are as in v0.1.4. `scion-server-v0.1.5-<target>.tar.gz` holds the server `scion` and `scn-v0.1.5-<target>.tar.gz` the client. Both are built for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer), `aarch64-apple-darwin` and `x86_64-apple-darwin`, and come with `SHA256SUMS` and `install.sh`.

## Changes

- **`scn remote`.** `scn remote -v`, `scn remote get-url` and `scn remote set-url [origin] URL` show or change the server and repository of a working copy. The new address must have the commits the working copy is on, which makes it suitable for a server's new IP or host name, a fork, or a migrated copy. Before this release the address saved at clone time could not be changed.
- **`scn login SERVER TOKEN`.** The token can be given as an argument, before or after the server. `--token` and `--with-token` still work.
- **`--help` for every command.**
  - Every argument has a description and a name that says what it takes, such as `[REV:]PATH`, `BRANCH`, `N` or `FILE`.
  - Everyday commands show examples.
  - Global options have their own heading.
  - `scn --help` groups the commands by what they are for, as `git --help` does.
- **git's spellings work.**
  - `clone -b BRANCH`, as well as `--depth` and `--single-branch`. A clone only downloads a snapshot, so these two change nothing.
  - `commit -m TITLE -m BODY`; each `-m` becomes a paragraph.
  - `log -5`, `log --pretty=oneline`.
  - `status -sb`, `status --porcelain`.
  - `diff --cached` / `--staged`. scn has no staging area, so these show the same changes as `diff`.
  - `branch -v`, `-a`, `--show-current`; `tag -l`.
  - `merge --no-ff`.
  - `config user.name NAME`, `config --list`, `config --unset KEY`.
  - `push [-u] origin BRANCH`, `pull --ff-only`.
  - `remote show`, `mv -f`.
- **Clear messages for git commands that scn does not have.** `push --force`, `init`, `fetch`, `stash` and `remote add` exit with code 2 and say what to use instead. `commit MESSAGE` without `-m` explains that the message goes after `-m`.
- **New options.**
  - `scn restore --source REV PATH` (`-s`) takes the files from another revision as local changes. git's `checkout REV -- PATH` now does the same.
  - `scn blame -L N,M` (also `N,+K`, `N`, `,M`, and repeatable) shows only some lines.
  - `scn diff --stat` and `scn show --stat` print git's diffstat.
