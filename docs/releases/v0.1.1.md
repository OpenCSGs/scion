A patch release of [v0.1.0](https://github.com/OpenCSGs/scion/releases/tag/v0.1.0), with a one-command installer.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
# for a team: authentication on, and the first administrator's token printed
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server --listen 0.0.0.0:7080
```

`install.sh` is also attached below. The packages are as in v0.1.0: `scion-server-v0.1.1-<target>.tar.gz` (the server `scion`) and `scn-v0.1.1-<target>.tar.gz` (the client), for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer), `aarch64-apple-darwin` and `x86_64-apple-darwin`, with `SHA256SUMS`. The image is `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.1` (linux/amd64 and linux/arm64).

## Changes

- **New: `install.sh`**, which downloads the release for the platform, checks it against `SHA256SUMS` and installs `scn`; with `--server` it also installs `scion` and runs it as a service. Beyond loopback it turns authentication on and creates the first administrator's token. See [deployment](https://github.com/OpenCSGs/scion/blob/main/docs/guide/deploy.md#release-binaries).
- **Fix: the server starts on a Linux without CA certificates** (such as the `ubuntu:22.04` image). v0.1.0 stopped at start with `invalid auth configuration: HTTP client: builder error`; the HTTP client for external identity providers is now created only when one is configured, and its error says to install `ca-certificates`.
