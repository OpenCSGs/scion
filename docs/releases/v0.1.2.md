A patch release of [v0.1.1](https://github.com/OpenCSGs/scion/releases/tag/v0.1.1): the macOS binaries are signed with OpenCSG's Developer ID.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

The packages are as in v0.1.1: `scion-server-v0.1.2-<target>.tar.gz` (the server `scion`) and `scn-v0.1.2-<target>.tar.gz` (the client), for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer), `aarch64-apple-darwin` and `x86_64-apple-darwin`, with `SHA256SUMS` and `install.sh`.

## Changes

- **Fix: `scn` and `scion` on macOS can reach other machines on the LAN.** v0.1.1's macOS binaries were ad-hoc signed, and macOS refuses LAN connections from such command-line tools (`scn doctor http://192.168.1.19:7080` failed with `No route to host`). They are now signed with the Developer ID, the hardened runtime and a secure timestamp, as `com.opencsg.scn` and `com.opencsg.scion`, so macOS asks for local network access instead.
