The first release of CSG Scion: server-first source control for monorepos, coding agents and CI, after Anthropic's [Redesigning source control](https://www.anthropic.com/engineering/redesigning-source-control).

## Downloads

| Package | Contents |
|---|---|
| `scion-server-v0.1.0-<target>.tar.gz` | `scion`: the server, the regional cache (`scion cache`) and the admin commands |
| `scn-v0.1.0-<target>.tar.gz` | `scn`: the client, with its local daemon |

Targets: `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer), `aarch64-apple-darwin` and `x86_64-apple-darwin`. Check downloads against `SHA256SUMS`.

The container image `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.0` (linux/amd64 and linux/arm64) holds both.

## Quick start on one machine

```sh
tar -xzf scion-server-v0.1.0-<target>.tar.gz && tar -xzf scn-v0.1.0-<target>.tar.gz
./scion-server-v0.1.0-<target>/scion server --lite --data-dir ./scion-data &
./scn-v0.1.0-<target>/scn repo create http://127.0.0.1:7080/mono
./scn-v0.1.0-<target>/scn clone http://127.0.0.1:7080/mono
```

See [Deployment](https://github.com/OpenCSGs/scion#deployment) for authentication, PostgreSQL + S3 and the container image.

## What is in it

- **Writes on the server:** commits are created on the server from the files they change; `scn land` rebases on the server when the branch moved, exactly once, with concurrent lands to one branch batched.
- **Fetch on demand and sparse checkouts:** clients fetch trees and files by id, so directories outside a sparse scope are never fetched.
- **History as server queries:** log, diff, blame, ancestry, merge bases, last commits per entry, directory statistics and archives.
- **Storage tiers:** Lite (SQLite + a local directory) and Standard (PostgreSQL + S3-compatible storage: MinIO, SeaweedFS, AWS S3 and others); objects are zstd-compressed and packed, and `scion admin repack` stores older versions as deltas.
- **Clusters and caches:** stateless server nodes behind a load balancer, a regional cache (`scion cache`) and a local daemon (`scn daemon`).
- **git compatibility:** `scn import git` keeps every commit's git SHA; every commit has a git-compatible SHA; most git commands work in `scn` as typed, including `scn clone http://host/REPO`.
- **Access control:** tokens, OIDC login, external issuers and authorization callbacks, ACLs by repository, ref and path; the server refuses to listen beyond loopback without authentication.
- **Operations:** redaction and purge, `scion admin fsck`, ref events (webhooks, NATS), pre-land checks, Prometheus metrics and OpenTelemetry tracing.
