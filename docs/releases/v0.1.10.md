`scn` gains `revert`, `cherry-pick`, several pending commits at once and `watch`, and the server records which commit a rebased commit was made as. There is nothing to migrate. A 0.1.10 client works with a 0.1.9 server, but `Rebased-from` appears only for commits that a 0.1.10 server landed.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

**Release packages.** As in v0.1.9, the server `scion` comes in `scion-server-v0.1.10-<target>.tar.gz` and the client in `scn-v0.1.10-<target>.tar.gz`, with `SHA256SUMS` and `install.sh`. The targets are:
- `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer);
- `aarch64-apple-darwin` and `x86_64-apple-darwin`.

**Docker image.** `opencsghq/scion:0.1.10` on Docker Hub, also as `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.10`, for `linux/amd64` and `linux/arm64`; both are also tagged `latest`.

## Changes

- **`scn revert REV`** undoes a landed commit as a new pending commit (`Revert "SUBJECT"`). Only that commit's changes are undone; later changes to the same files stay. When they overlap, you resolve the conflict with `scn resolve` and `scn commit`, or give up with `scn revert --abort`. For a merge commit, name the parent to keep with `-m 1`.
- **`scn cherry-pick REV`** applies a commit from another branch here as a pending commit. It keeps the commit's message, author and author time; whoever applies it is the committer, and `SCION_AUTHOR` does not replace the author. `-x` adds `(cherry picked from commit ID)` to the message, and `--abort` gives up after a conflict.
- **Several pending commits.** Successive `scn commit`s stack up and one `scn land` lands them all. `scn sync` rebases them one by one, and each commit keeps its own message; before, they were squashed into one and the earlier messages were lost. On a conflict, `sync` stops at that commit, and `scn commit` after `scn resolve` goes on with the rest. `uncommit` and `commit --amend` act on the newest commit. `status -sb` shows `ahead N`.
- **`scn watch`** follows branches on the server and prints each commit as it lands (`BRANCH  ID  AUTHOR  SUBJECT`), or with `--json` one object per move. `--count N` stops after N moves.
- **Rebased-from.** When the server rebases a commit as it lands, it records the commit as it was made in the `scion.rebased-from` extension. `scn log` and `scn show` print a `Rebased-from:` line, `watch` adds `(rebased from ID)`, and `--json` has `rebased_from`.
- **Fix: three-way merges.** A line merge whose result is the same as our file no longer makes an empty commit.
- **Fix: `--abort` with `SCION_AUTHOR` set.** `scn merge --abort` failed when `SCION_AUTHOR` was set, as it is for agents.
