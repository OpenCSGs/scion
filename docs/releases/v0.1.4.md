`scn` now looks like git: clone, import and archive show git-style progress, and every command prints what git prints for the same step. Conflicts between files added on both sides now get conflict markers. A server with no saved policy makes the `admins` group administrator.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

The packages are as in v0.1.3: `scion-server-v0.1.4-<target>.tar.gz` (the server `scion`) and `scn-v0.1.4-<target>.tar.gz` (the client). They are built for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer), `aarch64-apple-darwin` and `x86_64-apple-darwin`, and come with `SHA256SUMS` and `install.sh`.

## Changes

- **Progress like git.** When standard error is a terminal, `scn clone` prints `Cloning into 'mono'...`, `Listing files: N, done.` and `Receiving objects: 100% (n/n), 6.01 MiB | 3.20 MiB/s, done.`. `scn import git` prints `Importing commits:  45% (135/300)`, and `scn archive` prints `Receiving archive: SIZE | RATE`. The new global `-q` / `--quiet` turns off progress and notes; `--json` never shows them.
- **Output like git.**
  - `status` uses git's long format, with paths relative to the current directory; `status -s` gives `XY PATH` (`M  `, `A  `, `D  `, `UU`, `AA`, `UD`, `DU`).
  - `commit` prints `[main c1…] subject` and `N files changed`.
  - `land` (`push`) prints `To URL` and `old..new  main -> main`.
  - `sync` (`pull`) prints `Already up to date.`, `Updating a..b` / `Fast-forward`, or `Successfully rebased and updated main.`.
  - A conflicting `sync` or `merge` prints `CONFLICT (content): Merge conflict in PATH` for each file.
  - `switch` prints `Switched to branch 'x'`, and `merge` prints `Merge made by the 'scion' strategy.`.
  - `branch` and `tag` list names only, with `*` on the current branch; deleting one prints `Deleted branch x (was …).`.
  - `log` and `show` use git's commit format (`commit` / `Author` / `Date`), and `--oneline` now gives one line per commit.
  - `diff` uses git's headers (`diff --git`, `new file mode`, `index`, `/dev/null`); `--name-only` lists paths only, and the new `--name-status` adds the status.
  - `blame` uses git's format.
  - `clone`, `restore`, `merge --abort`, `archive -o`, and creating a branch or tag print nothing.
- **Fix: files added on both sides conflict with markers.** When `sync` or `merge` met the same new file on both sides with different contents, the file kept only your version and gave no sign of the other. It now holds conflict markers with both, as git does, and is reported as `add_add`.
- **Default policy: the `admins` group is administrator.** A server with no saved policy and no authorization callback lets the `admins` group manage policies and tokens. Anyone signed in can still read, write and land.

## Compatibility

Scripts that parse `scn`'s text output may need changes. `status` defaults to the long format, so use `-s` for the old style of one line per file. Branch and tag lists no longer show commit ids. The `--json` output is unchanged, except that deleting a branch or tag now gives the commit it pointed at in `changeset` (it was null). Scripts should use `--json`.
