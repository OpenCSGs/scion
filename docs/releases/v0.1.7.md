Clearer `scn` output when several people or agents land on the same branch, and server images on Docker Hub. Servers and clients work as in v0.1.6; there is nothing to migrate.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

**Release packages.** As in v0.1.6, the server `scion` comes in `scion-server-v0.1.7-<target>.tar.gz` and the client in `scn-v0.1.7-<target>.tar.gz`, with `SHA256SUMS` and `install.sh`. The targets are:
- `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer);
- `aarch64-apple-darwin` and `x86_64-apple-darwin`.

**Docker image.** The server image is `opencsghq/scion:0.1.7` on Docker Hub, also as `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.7`, for `linux/amd64` and `linux/arm64`. Both are also tagged `latest`, and the release workflow now pushes them for every release.

## Changes

- **`scn land` after a server rebase.** When the branch moved and the server rebased your commit:
  - the range starts at the branch's previous tip on the server, as `git push` shows it, so commits that others landed in between are visible;
  - a line `your commit c1519800b4cb is now c180bad0cc02` names the new id; `--json` lists them in `rewritten`.
- **Conflicts on land.** The hint now points to `scn sync`, then `scn resolve FILE`, `scn commit` and `scn land`, instead of a fresh clone. The message names the commit by its short id; the full id stays in the error's metadata.
- **`scn status`.** Its hint says that every change is included, since scn has no `add` step, and that `scn restore` discards changes to tracked files.
- **docker compose.** `deploy/compose` runs `opencsghq/scion:latest` instead of building from source; `SCION_IMAGE` picks another image, such as one built from a checkout (`docker build -t scion:dev .`). The MinIO in `deploy/dev` is `bitnamilegacy/minio:2023` from Docker Hub.
