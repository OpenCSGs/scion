A fix for `scn` 0.1.8, and a demo of agents landing together. Servers work as in v0.1.8; there is nothing to migrate.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

**Release packages.** As in v0.1.8, the server `scion` comes in `scion-server-v0.1.9-<target>.tar.gz` and the client in `scn-v0.1.9-<target>.tar.gz`, with `SHA256SUMS` and `install.sh`. The targets are:
- `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer);
- `aarch64-apple-darwin` and `x86_64-apple-darwin`.

**Docker image.** `opencsghq/scion:0.1.9` on Docker Hub, also as `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.9`, for `linux/amd64` and `linux/arm64`; both are also tagged `latest`.

## Changes

- **Fix: `--repo` inside a working copy.** In 0.1.8, revisions default to the working copy's commit (HEAD), but also when `--repo` named another repository, which has no such commit: `scn cat README.md --repo OTHER` failed with `NotFound` inside a working copy. HEAD is now the default only for the working copy's own repository; elsewhere it is `main`, as before 0.1.8.
- **A demo.** The README shows four agents landing on one branch while a monitor watches it on the server; [docs/demo](https://github.com/OpenCSGs/scion/tree/main/docs/demo) has the scripts that record it.
