`scn` behaves more like git when several people or agents land on one branch: it compares the working copy with the branch on the server, counts changed lines, and keeps commit times in the order commits landed in. Servers and clients work as in v0.1.7; there is nothing to migrate.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

**Release packages.** As in v0.1.7, the server `scion` comes in `scion-server-v0.1.8-<target>.tar.gz` and the client in `scn-v0.1.8-<target>.tar.gz`, with `SHA256SUMS` and `install.sh`. The targets are:
- `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer);
- `aarch64-apple-darwin` and `x86_64-apple-darwin`.

**Docker image.** `opencsghq/scion:0.1.8` on Docker Hub, also as `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.8`, for `linux/amd64` and `linux/arm64`; both are also tagged `latest`.

## Changes

- **Revisions default to HEAD.** In a working copy, `scn log`, `show`, `cat`, `ls`, `blame`, `branch NAME` and `tag NAME` start from the working copy's commit, as in git. `main` names the branch on the server, and `origin/main` means the same.
- **The server's history without syncing.** `scn log main` and `scn diff HEAD main` show what others landed since your last `scn sync`; `scn fetch` now says so.
- **`scn status` compares with the server.** It says how many commits the branch on the server has that the working copy lacks, and `-sb` prints `## main [ahead 1, behind 2]`. This asks the server once (twice when the branch moved), gives up after 2 seconds, and is left out offline. `-s` and `--porcelain` without `-b` stay local; `--no-ahead-behind` skips it.
- **`scn commit` counts lines.** It prints `1 file changed, 3 insertions(+), 1 deletion(-)`, and `--json` has `insertions` and `deletions`. The old versions are fetched in one batch, for commits of up to 1000 files whose old versions total at most 4 MiB.
- **Commit times follow the landing order.** When the server rebases a commit, its committer time becomes at least that of the commit it now follows; the author time stays. `scn log` and `scn show` print a `CommitDate:` line when it differs from the author date. The rebase stays deterministic.
- **Land conflicts** name up to three conflicting paths in the message.
- **`scn land`** prints `Your commit X is now Y` as a line of its own.
