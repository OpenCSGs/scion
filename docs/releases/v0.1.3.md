A patch release of [v0.1.2](https://github.com/OpenCSGs/scion/releases/tag/v0.1.2) that completes its macOS fix: `scn` and `scion` can now ask for local network access.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

The packages are as in v0.1.2: `scion-server-v0.1.3-<target>.tar.gz` (the server `scion`) and `scn-v0.1.3-<target>.tar.gz` (the client), for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer), `aarch64-apple-darwin` and `x86_64-apple-darwin`, with `SHA256SUMS` and `install.sh`.

## Changes

- **Fix: `scn` and `scion` on macOS can reach other machines on the LAN.** v0.1.2 signed them with the Developer ID but did not fix the problem. A signed command-line tool goes through the local network check under its own identity, and without an `NSLocalNetworkUsageDescription` macOS refuses the connection without asking, so `scn doctor http://192.168.1.19:7080` still failed with `No route to host`. Both binaries now embed an Info.plist with it. The first connection to the LAN asks for access; allow it, or turn it on later under System Settings → Privacy & Security → Local Network.
- **`install.sh` works without a terminal.** Over `ssh host sh install.sh`, sudo could not ask for a password and the install failed. It now uses sudo only when sudo needs no password or has a terminal; otherwise it installs to `~/.local/bin` and, when that is not on `PATH`, adds it to the login shell's profile once.
